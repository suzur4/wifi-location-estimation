最初に読む

Wi-Fi位置推定 実験ラボ

仮想の電波データを変えながら、PCのエリアをどう推定できるか考える教材です。データはすべて模擬値です。推定している対象は架空のPCで、実在する先生や学校の設備は扱いません。

すぐに始める

  1. ZIPで受け取った場合は、右クリックして「すべて展開」を選びます。展開済みのフォルダーなら、この手順は不要です。
  2. このファイルと同じフォルダーにある index.html をダブルクリックします。EdgeやChromeなど、PCで使えるブラウザで開きます。
  3. ラボが開いたら「実験A」でスライダーを1つ動かします。グラフと場所の推定が変わるか確かめます。
  4. 教材と記録用紙は 印刷できる教材ページ を開きます。印刷する資料を選び、「印刷画面を開く」を押します。

アプリはPC内のHTMLだけで動きます。Python、Node.js、npm、管理者権限、インターネット接続の準備は不要です。ZIPの中から直接開くと別ファイルへのリンクが使えないことがあるので、先にフォルダー全体を展開します。実際の学校PCでの動作可否は、当日の端末ルールに従って事前確認してください。

生徒向け操作ガイド

どの実験でも、先に予想を1文書く、1つだけ変える、結果を記録するの順で進めます。何を試したかは 実験ワークシート に記録できます。

実験 最初にすること 確かめること
A 電波強度 AP A〜Dのスライダーを1つ動かす。戻すときは「初期値に戻す」 RSSIの大小と最強AP。僅差や同じ値のときはどうなるか
B 平均と中央値 1行に1つのRSSIを書き、「外れ値を1件追加」を試す 値の個数、平均と中央値、標準偏差。変える前後の差
C APの数 シナリオ・シードを決め、APのチェックを切り替える ON/OFFで最後の観測に基づく推定が変わるか。「同じ条件でやり直す」はシナリオ・シードを保ち、APを全ONにする
D 方式の比較 Cと同じ入力で、最強AP・平均RSSI・簡易フィンガープリントを見比べる 3方式が見る観測、結果の違い、その理由
E プログラムを変える 2つの判定条件の片方だけ数値を変え、「コードを試す」 ルールと結果の関係。「見本に戻す」で比較をやり直せる

CとDで比べるとき　シナリオは模擬場面、シードは同じ模擬データを作り直すための番号です。CとDは5回の模擬観測とAP設定を共有します。シードを入力し直したら「同じ条件でやり直す」を押して反映します。変更する前にシナリオ・使用中のシード・AP構成・模擬上の正解を書きます。ONのAP数と、最後の行で実際に値があるONのAP数は分けて記録します。Dの「初期値に戻す」は方式だけを最強APに戻します。

記録を残すとき　実験Cでは「実験前の予想」と「結果メモ」を書き、「条件と結果を記録」を押します。「記録CSVを保存」を選ぶか、CSV欄をコピーします。この記録はCの簡易フィンガープリント用です。Dの最強AP・平均RSSIやA・B・Eの結果はワークシートへ書きます。学校PCでダウンロードが制限される場合は、紙や許可されたローカルのテキストファイルへ転記してください。画面の記録はタブ内の一時状態なので、閉じる前に残します。

自分に合う進め方

  • 初めての人　教材1の図を見てAを操作します。Bで平均と中央値の片方を手計算で確かめ、気付いたことを記録します。Eは数値1つの変更から始めます。
  • 実験に慣れている人　CまたはDで、同じ複数シナリオを2条件ずつ試します。正解・誤表示・不明を分け、分母と一緒に報告します。
  • プログラム経験がある人　Eの発展演習で境界値を設計し、複製したファイルで1か所を編集します。うまくいかなかった入力も再現できるように残します。
  • 時間が短いとき　Aで操作をつかみ、B・C・Dから班の疑問に合う実験を1つ選びます。Eは次回に回せます。

教材1　Wi-Fiと位置推定の基本

今日の問い　近くにあるアクセスポイントが、いつも一番強く見えるでしょうか。

Wi-Fiは電波を使う

Wi-Fiは、機器が電波で通信する仕組みです。スマートフォンやPCは、アクセスポイント（AP）を通してネットワークに接続できます。接続しているAPは1つでも、周囲に複数のAPの電波が届くことがあります。

仮想AP A  )))  壁  )))  ┌───┐  (((  仮想AP B
                          │ PC│
                          └───┘
             PCに届く強さはAPごとに違う
言葉 何を表すか 架空の例
SSID Wi-Fiのネットワーク名。同じ名前を複数のAPが使える Lab-WiFi
BSSID 個々の無線通信のまとまり（BSS）を識別する値。物理機器1台が複数持つこともある 教材では実際の値を使わず A・B・C・D と呼ぶ
RSSI 受け取った信号の強さの指標。この教材ではdBmを使う −42 dBm、−71 dBm

RSSIが −42 dBm と −71 dBm なら、数の大きい−42 dBmの方が強い。絶対値だけで比べると逆になるので、数直線に置いて考えてください。棒の長さは信号の見比べに使えます。dBmは割合の単位ではなく、棒が2倍に見えても「電波が2倍」とは読めません。

場所の見当を付ける

あるエリアでAが強くBが弱い傾向があり、別のエリアでは逆だとします。新しい測定がどちらのパターンに似ているか比べると、PCのエリアを推定できます。あらかじめ測って作る比較用のパターンを指紋（フィンガープリント）と呼びます。人の指紋を集めるわけではありません。

近くても壁を挟むと弱くなったり、電波が反射したり、PCの向きや端末の違いで値が変わったりします。別のエリアで似たパターンになることもあります。最強APは手がかりの一つです。PCの場所の推定から、その利用者がそこにいると判断することもできません。

実験Aで確かめる

  1. APを2台選び、どちらを強くすると推定が切り替わりそうか予想する。
  2. 片方だけのRSSIを少しずつ変える。切り替わる前後の値を記録する。
  3. 2台が同じ強さのとき、どんな表示なら利用者が誤解しにくいか考える。

問いの例。電波が弱くなったとき、「PCが遠くなった」以外の説明を2つ考えてください。画面で変えた値はすべて模擬値です。学校のAP、SSID、BSSIDを調べる作業はありません。

大学生向けの補足資料は、本体リポジトリの docs/NETWORK.md と docs/SOURCES.md にあります。配布用フォルダーでの活動は、この教材だけで進められます。

教材2　疑問を実験に変える

今日の問い　「APを増やせばよくなる」という予想を、どんな結果なら見直せるでしょうか。

段階 すること 実験Cでの例
1　疑問を見つける 「なぜ」「いつ」「何を変えると」で問いを作る APを1台足すと、推定は毎回よくなる？
2　仮説を立てる 予想とその理由を、測る前に書く 弱いAPを足すと違う場所の手がかりも増えるので、正解が増えそう
3　方法を考える 変える条件・そろえる条件・測る結果を決める 同じ場面で、同じ方式のままAP構成だけ変える
4　条件をそろえて試す 同じ条件の組を比べ、元の条件に戻せるようにする Aだけの状態と、AにBを足した状態を順に試す
5　結果を記録する 予想と違う結果もその場で記録する 真のエリア、RSSI、使用AP、推定、正誤・不明
6　グラフで比べる 横軸・縦軸・単位を決め、条件を並べる 横軸はAPの構成、縦軸は正しく表示した回数
7　考察する 観察事実と、事実を説明する自分の考えを分ける 「3回中1回改善した」は事実。「Bが区別に効いた」は説明の候補
8　次の実験を考える 疑問を一つ選び、次に変える条件を決める 同じAP構成で、弱いAPだけを外れ値にしたら？

条件をそろえる

  • APの数とどのAPを使うかは別です。1台の状態に別の1台を足す比較では両方が変わります。「AからA＋Bに変えた」と組を明記します。
  • 使う方式の違いを知りたいなら、場面・RSSI・APのON/OFFを固定して実験Dの方式だけ切り替えます。
  • 正解は模擬場面の「正解エリア」など、推定の外から決めたものを使います。推定結果を見て正解を書き換えません。正解が用意されていない自由入力では、正解率よりも「表示がどう変化したか」を記録します。
  • 模擬場面を3種類試すなら、どの条件でも同じ3種類を使います。場面数は 試行数 です。同じ固定入力をリセットして何度も見ることは、操作の再現確認です。独立した測定が増えたとは数えません。

正解・誤表示・不明を分ける

真のエリアが分かる6試行で、正しい表示が3件、誤った表示が1件、不明が2件なら、正解率は3/6、誤表示率は1/6、不明率は2/6です。結果を表示した4件だけに限る正答割合は3/4です。分母が異なるので、数字だけ並べず 3/6、3/4 と件数を示してください。

「よい」方式の意味も決めます。結果が一時的に出ないことと、間違ったエリアへ人を案内することのどちらを避けたいですか。結果を見てから都合のよい基準に変える場合は、次の実験として分けて記録します。

記録先は 実験記録ワークシート。

教材3　データ分析と誤差

今日の問い　1回だけ大きく外れた測定を入れると、データの見え方はどう変わるでしょうか。

平均と中央値

あるAPを静止したPCから5回測ったと仮定します。単位はdBmです。

データ 小さい順に並べた値 平均 中央値
元の5個 −62、−61、−60、−59、−58 −60 −60
−90を1個追加 −90、−62、−61、−60、−59、−58 −65 −60.5

平均は値の合計を個数で割ります。中央値は並べたときの真ん中の値で、偶数個なら中央2個の平均です。上の例は教材用の計算練習です。画面の初期値とは異なる場合があるので、実験Bでは画面の測定値を自分で書き取って確認します。

他と大きく違う値を外れ値と呼ぶことがあります。大きく外れた値に、機器の誤りや環境の変化など、意味がある場合もあります。消す前に「何を知るために、どういう基準で除くか」を決めます。

ばらつきと測定回数

  • ノイズは、知りたい値に重なる意図しない変動です。信号を測る向き、人や物の動き、機器の揺らぎなどが値に影響することがあります。
  • 分散は、各測定値と平均の差を二乗し、その平均をとったものです。ここでは手元にある値全体の広がりを記述します。元の5個では平均との差が−2、−1、0、1、2なので、分散は (4＋1＋0＋1＋4)÷5＝2 です。
  • 標準偏差は分散の平方根です。この例では約1.41 dBです。大きいほど平均から離れた測定が多い傾向があります。場所を変えた複数エリアのデータを混ぜると、場所による差までばらつきに含まれます。
  • 測定回数を増やすと、たまたまのゆらぎの影響を抑えられる場合があります。同じ偏りが繰り返される場合や、似た条件の連続測定では、回数だけで偏りや依存関係は解消しません。

実験Bでグラフを読む

  1. RSSIの測定値を書き取り、平均と中央値がどこに来るか予想します。
  2. 測定値を1つ変更するか外れ値を加えます。変える前後で値の個数を記録してください。
  3. 1回目から順番に追えるグラフでは、横軸が測定番号、縦軸がRSSIです。分布や棒グラフでは並び順の意味が違うので、まずラベルを見ます。
  4. 平均と中央値がそれぞれ何dB動いたか書きます。表示上の丸めと計算の結果を分けて考えます。

考える問い　普段の静止PCの信号を知るときと、本当に環境が変わったことを早く知りたいときで、選びたい処理は同じですか。

教材4　手順をプログラムにする

今日の問い　同じ数字を見たとき、どんなルールなら「位置不明」にしますか。

アルゴリズムは答えにたどり着く手順

「測定を読む → 見比べる → 場所を表示する」は手順です。手順を誰が実行しても再現できるように、条件をはっきり書いたものがアルゴリズムです。

部品 何に使うか この実験の例
配列 順番に並ぶ値をまとめる 1つのAPの測定値 [-62, -63, -61]
繰り返し 同じ操作を各要素に行う 各RSSIを合計に加える
条件分岐 条件によって動作を変える 信号が弱すぎれば位置不明
関数 入力を受け、まとまった仕事をする 配列を受け取り平均を返す関数 
function mean(values) {
  if (values.length === 0) return null;  // 平均を計算する材料がない
  let sum = 0;
  for (const value of values) {
    sum += value;
  }
  return sum / values.length;
}

空の配列の平均は計算できません。欠測を勝手に0 dBmとして足すと、非常に強い観測があったかのような意味になります。測れなかったことと、弱い信号を測ったことを区別します。

実験Dで方式を比べる

同じシナリオ・シード・AP構成で、次の方式の答えを見比べます。

方式 実際にする計算 気を付けること
最強AP 最後の測定行で、ONのAPのうちRSSIが最大のAPに対応する部屋を返す 最大値が同じAPが複数なら保留。最後の1回が外れ値だと答えが変わりやすい
平均RSSI ONのAPごとに測れた値を平均し、平均が最大のAPに対応する部屋を返す 最大の平均値が複数なら保留。平均の計算はAPごとに行う
簡易フィンガープリント 最後の測定行を、各部屋の登録パターンと比べる。共通する観測APのRSSI差を二乗し、その平均の平方根を距離とする 距離が小さいほど似ている。共通APが2台未満、最小距離が18 dBを超える、1位と2位の差が2 dB未満のいずれかなら保留する

たとえば観測がA −54、B −66、ある部屋の登録値がA −50、B −70なら、差は−4と4です。距離は √((16＋16)÷2)＝4 dB。別の部屋も同じ計算で比べます。

ラボでは、部屋ごとの代表的なパターンを1つずつ登録して比較します。多くの学習サンプルから近いk個を選んで多数決するk-NNとは別の簡略版です。実験ラボの結果を、本体システムの評価値として扱いません。

実験Eで小さく変更する

  1. 「プログラムを変える」を開きます。実験Aの現在のRSSIを確認し、何も変えずに「コードを試す」を押して変更前の結果を記録します。
  2. コメントで指定された MIN_RSSI と MIN_GAP のどちらか一方だけ、数値を書き換えます。初めに「表示されやすくなる／されにくくなる」を予想してください。
  3. 「コードを試す」で表示を比べます。意図どおりにならなければ、変えた値・現在のRSSI・最強と次点の差を照合します。
  4. 「見本に戻す」で元のルールに戻します。入力値と結果が元に戻るか確認します。

MIN_RSSI は最強の信号が弱すぎないかを決める下限（−120〜0 dBm）、MIN_GAP は1位と2位をどれだけ区別したいかを決める差（0〜120 dB）です。画面の入力欄ではこの2つの数値を検査して既定の関数へ渡します。任意のJavaScriptを実行する仕組みはありません。

経験者　発展演習と変更見本を開いて、同値・AP1台・欠測・閾値ちょうどの入力を表にします。元の index.html を同じフォルダーへ別名でコピーし、テキストエディターで 実験E 編集ここから または function estimateExerciseArea を探します。1条件だけ変えて保存し、コピーをブラウザで開き直します。元ファイルを開き直せば比較に戻れます。

考える問い　閾値を厳しくしたとき、誤表示が減る可能性と、位置不明が増える可能性の両方をどう確かめますか。

復元用の関数

// 実験Eの復元用。index.html の「実験E 編集ここから」で囲まれた関数と交換します。
function estimateExerciseArea(readings, overrides = {}) {
  // 変更1: 一番強いAPがこの値より弱い場合は保留。
  const MIN_RSSI = -72;
  // 変更2: 上位2台の差がこの値より小さい場合は保留。
  const MIN_GAP = 4;
  const ordered = [...readings].sort((a, b) => b.rssi - a.rssi);
  if (ordered.length < 2) return null;
  const [first, second] = ordered;
  if (first.rssi < (overrides.minRssi ?? MIN_RSSI)) return null;
  const gap = first.rssi - second.rssi;
  if (gap === 0 || gap < (overrides.minGap ?? MIN_GAP)) return null;
  return first.area;
}

教材5　カルマンフィルタと有限オートマトン

今日の問い　測定値を落ち着かせることと、答えを表示してよいか決めることは、どう違うでしょうか。

2つの仕事

測ったRSSI ──→ 数値を見積もる ──→ エリア候補を選ぶ ──→ 表示してよいか決める
                   ↑                                          ↑
            カルマンフィルタ                            有限オートマトン

カルマンフィルタは、前の見積もりと新しい測定を組み合わせる計算です。前の見積もりがどの程度変わり得るか、新しい観測がどの程度ばらつくかを考えます。静止したPCのRSSIを測るなら、急な1回の変化だけで見積もりを大きく動かさない使い方ができます。設定によっては本当の変化への反応も遅れます。実験Bの平均・中央値と同じ「測定値の変動に対処する」仲間ですが、更新方法が異なります。

有限オートマトン（FSM）は、有限個の状態と、入力が来たときの状態の移り方を決めたルールです。RSSIを数値的に補正する機能ではありません。たとえば推定器から理科室が候補として1回出ただけなら待ち、別の新しい測定でも同じ場所が候補になったら表示する、という制御に使います。

紙で動かす状態遷移図

次は説明用のルールです。確認に必要な回数を 2回 と仮定します。選ぶ回数と待ち時間の関係は実験で検討します。

[不明・期限切れ] ── 新しい有効な候補 ──▶ [候補]
[候補] ── 同じ候補を新しい測定で確認 ──▶ [確定]
[候補・確定] ── 異なる有効な候補 ──▶ [候補]
[候補・確定] ── 信頼できる候補がない ──▶ [不明]
[候補・確定] ── 測定が古くなる ──▶ [期限切れ]
非公開を選んだら、どの状態でも直ちに表示を止める。
今の状態 起きたこと 次の状態 画面での扱い

班の演習　記録係が「理科室、理科室、図書室、同じ図書室の画面を更新、図書室の新測定、期限切れ、非公開」と読み上げ、もう1人が毎回の状態と表示を書きます。「2回」は教室の説明用です。実際の位置や移動を記録する演習ではありません。

別のFSMを見つける

  • 信号機では赤・青・黄の状態をタイマーなどで切り替えます。交通の安全に関わる条件は、単純な色の順番だけでは表現できません。
  • 自動ドアでは閉じている・開いている・閉じかけているを区別します。閉じかけに人を検知したとき、閉じ切るまで待つべきか考えます。
  • ゲームでは待機・プレイ中・一時停止・終了で同じボタンの働きが変わることがあります。連打を新しいイベントとして何度も数えてよいか考えます。

考える問い　1回で表示する仕組みと3回待つ仕組みでは、間違いと待ち時間のどちらがどう変わりそうですか。「新しい測定が来ない」ときも含めて、比較する入力列を自分で作ってください。

教材6　同じ考え方を、別の問題で使う

実験で使った計算・ルール・記録方法は、対象を変えても使えます。同じ部分と、設計し直す部分を分けて考えます。

ラボの考え方 → 別の問題 同じ点 異なる点と新しい判断
RSSIの平均・中央値 → 温度センサー 時々ばらつく値から、代表値を求める 温度は℃、周囲が暖まる変化は消したくない。測る間隔や、変化に追いつく時間を決める
カルマンフィルタ → GPSや速度計のノイズ処理 直前の見積もりと新しい観測を組み合わせる 動く対象では位置・速度・加速度などが候補。停止を想定したRSSI用のモデルをそのまま使えない。観測間隔と運動の仮定を決める
フィンガープリント → 特徴量で葉や楽器音を分類 複数の特徴を一組にして、ラベル付きの見本と比べる 葉なら長さ・幅・葉脈、音なら周波数や強さなど、何を特徴にするかが変わる。照明、マイク、対象の個体差も考える
k-NN → 画像・データの分類 似ている見本をk個選び、ラベルの票を数える 画像の画素をそのまま使うと大きさや明るさに影響されることがある。どの違いを距離に含めるか、特徴の尺度やkを別データで検討する
有限オートマトン → 自動ドア・ゲーム・ロボット制御 今の状態とイベントに応じて、次の状態と動作を決める ドアなら人の検知と挟み込み防止、ゲームなら残り時間、ロボットなら停止条件が重要。誤った遷移の影響に合わせて優先順位を決める
グラフと条件の比較 → 自然科学の実験 横軸・縦軸・単位を決め、同じ条件の結果を比べる 植物の発芽なら光・水量・温度などの交絡を考える。毎日同じ個体を測った値を、別個体の独立測定とは数えない

小さな応用設計

次の題材を1つ選ぶか、自分たちで提案します。

  • 教室の温度が一瞬だけ上がる。窓を開ける通知を出すには何回の測定がほしいか。
  • 手描きの○と△を分類する。傾けても変わらない特徴をどう選ぶか。
  • ゲームの「待機」「プレイ中」「一時停止」「終了」を設計する。同時に終了と再開が来たらどちらを優先するか。
  • ロボットが壁の近くで止まる。センサーが値を返さない場合、どんな状態にするか。

ノートに、①入力、②出したい答え、③どの考え方を移すか、④元の問題と違う条件、⑤安全側の動作、⑥どういう結果で案を見直すかを書きます。題材は日常の疑問で構いません。

答えがまだない問い

  • どの場面で「分からない」と表示することが、かえって役立つでしょうか。
  • 分類に使う特徴が1つ欠けたとき、残りだけで答えられるかをどう試しますか。
  • すぐ応答することと誤作動を減らすことが両立しにくい例を、教室・家・部活から探せますか。
  • 同じデータを見た別の班が違う結論を出したら、どの条件と記録を比べますか。

選んだ応用例は 振り返りシート または 発表テンプレート に残してください。

事前確認 学校の同型端末でラボと教材を開き、A・B・Cとリセットを短く試す。実機での動作条件は学校側で確認する
記録 印刷したワークシート、筆記具、保存を許可したローカルの場所
端末が使えない場合 紙のRSSI表、外れ値カード、FSM状態表。進行案に代替手順あり

ラボのためにインターネット接続、外部サービス、アプリのインストール、管理者権限は不要です。学校のネットワーク設定に触れず、仮想APと模擬データだけを使います。教員の実名・端末ID・学校のSSID/BSSIDを記録欄へ入力しません。

役割と成果

  • 先生は活動の時間・端末の扱い・配布や保存の可否を調整します。
  • 大学生は教材と操作環境を準備し、問いかけで班の比較・考察を支援します。
  • 高校生は疑問を選び、予想・条件・操作・記録・説明を担当します。行ったプログラム変更があれば内容を残します。

結果の良し悪しより、①実験前の仮説、②1つ変えて他をそろえた比較、③条件・値・分母の記録、④模擬条件で言える範囲、⑤次の問い、を見ます。各項目をそろえた小さな1回で十分です。

活動後

学校と相談して、発表の有無や持ち時間を決めます。聖徳大学等で共有する場合は 発表用テンプレートを用い、事前にあった教材やシステム、大学生の支援、班が実際に行った実験・分析を分けて説明します。

具体的な時間配分と声かけは 60分の進行案。資料は 印刷できる教材ページから開けます。

先生・進行役

進行役向け　よくある質問

先に生徒の予想や観察を聞き、必要な場合にだけ説明例を使います。

開き方と操作

ZIPの中で開いたら教材リンクが使えない

展開したフォルダー全体を確認し、そこにある index.html をブラウザで開きます。 materials.html も同じ階層に置きます。端末の制限で開けない場合は、学校の担当者に確認するか 紙の代替へ切り替えます。

PythonやNode.js、学校のWi-Fiは必要か

ラボを実行するための準備はブラウザと配布フォルダーです。CSS・JavaScriptと模擬データをHTML内に含めています。授業で操作するのは仮想APと仮想測定値だけです。mainブランチにある教員PCエリア案内アプリのサーバー起動手順は、この教材の利用には必要ありません。

CSVを保存できない／途中で閉じそう

CSV欄をコピーして学校で許可された保存先へ置くか、ワークシートに必要な条件と結果を転記します。画面の記録はタブを閉じると消えます。学校の端末に任意の拡張機能を入れる必要はありません。

同じ条件に戻したのに結果が違う

シナリオ、シード、APのON/OFF、比較する方式を照合します。「同じ条件でやり直す」はAPを全ONに戻します。意図して欠損を作った比較では、当時のAP構成を記録から再設定します。A・Bは「初期値に戻す」、Eは「見本に戻す」で比べます。

Eのコードを編集したが変わらない

「コードを試す」を押したか、編集した数値の条件を今回のRSSIがまたぐか確認します。画面内で変更できるのは指定された2つの数値です。コピーしたHTMLを変更した場合は、保存したコピーを開き直し、ファイル名を確認します。

結果を読む

負の値はどう比べるか

−56と−65なら−56の方が大きく、このラボで強いRSSIです。数直線の0に近い方を指してもらいます。欠測の空欄は0 dBmとして扱いません。

Bの値を手計算で確かめたい

初期値 −62、−63、−61、−62、−64 の平均は −62.4 dBm、中央値は −62 dBm です。−25を1件追加すると、平均は約 −56.17 dBm、中央値は −62 dBm です。説明を先に読むより、班に「真ん中に来る二つの値は？」と尋ねて確かめてもらいます。

APが増えれば正解が増えるか

追加したAPが部屋の区別に役立つ場合も、外れ値や似た信号で判定を難しくする場合もあります。どのAPを足したか、他の条件をそろえたか、真のエリアが決まっているかを確認します。1場面の結果はその場面についての説明です。

位置不明は失敗か

誤った場所へ案内することを避けるため、手がかりが足りないときに保留する設計です。表示しないことにも利用者の不便があるため、誤表示・不明・待ち時間を別々に考えます。

カルマンフィルタとFSMはどちらを選ぶのか

仕事が違います。カルマンフィルタは数値の見積もり、FSMは候補を表示できる状態かの判定です。使う順序と条件を決めれば両方使えます。両方を使った場合に良いかは、比較する条件と重視する結果によります。

範囲と発表

この実験で学校の位置推定性能を言えるか

ラボの数値・部屋・APは模擬設定です。教室などの本当の電波強度、教員PCの種類、設備の管理方式は調べていません。発表では「この模擬条件では」と範囲を示し、実機で試すなら学校の許可を得た別計画として扱います。

大学生が作ったものを、班の発表でどう扱うか

使った教材や基盤を紹介し、班が決めた問い、比較した条件、測った結果、解釈、コードの変更点を分けて書きます。班が実施していない部分を自分たちの成果には含めません。
