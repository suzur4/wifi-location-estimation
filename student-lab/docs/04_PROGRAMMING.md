# 教材4　手順をプログラムにする

**今日の問い**　同じ数字を見たとき、どんなルールなら「位置不明」にしますか。

## アルゴリズムは答えにたどり着く手順

「測定を読む → 見比べる → 場所を表示する」は手順です。手順を誰が実行しても再現できるように、条件をはっきり書いたものが**アルゴリズム**です。

|部品|何に使うか|この実験の例|
|---|---|---|
|配列|順番に並ぶ値をまとめる|1つのAPの測定値 `[-62, -63, -61]`|
|繰り返し|同じ操作を各要素に行う|各RSSIを合計に加える|
|条件分岐|条件によって動作を変える|信号が弱すぎれば位置不明|
|関数|入力を受け、まとまった仕事をする|配列を受け取り平均を返す関数|

```javascript
function mean(values) {
  if (values.length === 0) return null;  // 平均を計算する材料がない
  let sum = 0;
  for (const value of values) {
    sum += value;
  }
  return sum / values.length;
}
```

空の配列の平均は計算できません。欠測を勝手に0 dBmとして足すと、非常に強い観測があったかのような意味になります。測れなかったことと、弱い信号を測ったことを区別します。

## 実験Dで方式を比べる

同じシナリオ・シード・AP構成で、次の方式の答えを見比べます。

|方式|実際にする計算|気を付けること|
|---|---|---|
|最強AP|最後の測定行で、ONのAPのうちRSSIが最大のAPに対応する部屋を返す|最大値が同じAPが複数なら保留。最後の1回が外れ値だと答えが変わりやすい|
|平均RSSI|ONのAPごとに測れた値を平均し、平均が最大のAPに対応する部屋を返す|最大の平均値が複数なら保留。平均の計算はAPごとに行う|
|簡易フィンガープリント|最後の測定行を、各部屋の登録パターンと比べる。共通する観測APのRSSI差を二乗し、その平均の平方根を距離とする|距離が小さいほど似ている。共通APが2台未満、最小距離が18 dBを超える、1位と2位の差が2 dB未満のいずれかなら保留する|

たとえば観測がA −54、B −66、ある部屋の登録値がA −50、B −70なら、差は−4と4です。距離は `√((16＋16)÷2)＝4 dB`。別の部屋も同じ計算で比べます。

ラボでは、部屋ごとの代表的なパターンを1つずつ登録して比較します。**多くの学習サンプルから近いk個を選んで多数決するk-NNとは別の簡略版**です。実験ラボの結果を、本体システムの評価値として扱いません。

## 実験Eで小さく変更する

1. 「プログラムを変える」を開きます。実験Aの現在のRSSIを確認し、何も変えずに「コードを試す」を押して変更前の結果を記録します。
2. コメントで指定された `MIN_RSSI` と `MIN_GAP` のどちらか一方だけ、数値を書き換えます。初めに「表示されやすくなる／されにくくなる」を予想してください。
3. 「コードを試す」で表示を比べます。意図どおりにならなければ、変えた値・現在のRSSI・最強と次点の差を照合します。
4. 「見本に戻す」で元のルールに戻します。入力値と結果が元に戻るか確認します。

`MIN_RSSI` は最強の信号が弱すぎないかを決める下限（−120〜0 dBm）、`MIN_GAP` は1位と2位をどれだけ区別したいかを決める差（0〜120 dB）です。画面の入力欄ではこの2つの数値を検査して既定の関数へ渡します。任意のJavaScriptを実行する仕組みはありません。

**経験者**　[発展演習](../exercises/CHANGE_A_RULE.md)と[変更見本](../examples/choose-area.js)を開いて、同値・AP1台・欠測・閾値ちょうどの入力を表にします。元の `index.html` を同じフォルダーへ別名でコピーし、テキストエディターで `実験E 編集ここから` または `function estimateExerciseArea` を探します。1条件だけ変えて保存し、コピーをブラウザで開き直します。元ファイルを開き直せば比較に戻れます。

**考える問い**　閾値を厳しくしたとき、誤表示が減る可能性と、位置不明が増える可能性の両方をどう確かめますか。
