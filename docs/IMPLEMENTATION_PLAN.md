# 初期実装の計画と判断記録（2026-11-04）

この文書は初期プロトタイプの設計判断を残した履歴である。現在の実装範囲は[要件](REQUIREMENTS.md)、構成は[アーキテクチャ](ARCHITECTURE.md)、これからの作業は[開発計画](NEXT_STEPS.md)を参照する。サーバーの導入とFSMの統合は、この初期計画の後に追加された。

初期設計は開発依頼文を基に行い、同日受領した研究メモとの実験番号・Phase区分の違いを[対応表](MEMO_ALIGNMENT.md)に整理した。以下のPhaseは最初の開発依頼文の区分である。

1. Phase 1: データ型、収集インターフェース、責務境界を決め、Python 3.12環境を構築する。
2. Phase 2: 固定シードの模擬観測、CSV/UJI入力、独立したRSSIフィルタ、共通推定エンジンを作る。
3. Phase 3: セッション単位の学習・検証・テスト分割でA〜Hを比較する。検証集合だけで閾値を選び、CSV/JSON/PNG/Markdownに保存する。端末・日付を分離した補助評価も行う。
4. Phase 4: 最新状態だけをSQLiteに保存するFastAPI、架空教員の検索・一覧・開発管理・研究画面を実装する。
5. Phase 5: 数値・入力異常・不明判定・API情報分離・画面機能をテストし、起動と画面を確認する。
6. Phase 6: 学校の許可と機器仕様に依存する収集は実装上無効のまま、接続条件とPoC手順を文書化する。

## 設計判断

- WindowsブラウザからRSSIを取得できるとは仮定しない。収集と推定を交換可能にし、最初は模擬・CSV・公開データだけを使う。
- 推定対象はPCのエリア。連続的な人の移動・速度・軌跡モデルを作らない。フィルタは同一端末・同一静止測定セッションに限定する。
- 生徒用APIの型を管理データから分離し、非公開の場合は時刻と理由も返さない。端末識別子、AP、RSSIを生徒画面に渡さない。
- SQLiteには教員情報・設定・教員ごとの最新観測を保存し、結果は取得時に計算する。研究用の匿名・模擬観測ファイルはこれと独立する。
- 校内認証基盤が不明なため、開発管理APIは設定可能なBearerトークンで保護する。未設定時は起動ごとにランダムなトークンを作る（2026-11-04に固定の初期値を廃止）。実運用認証の代替と扱わない。
- まず説明可能なk-NN等を比較する。RSSIの一次元線形モデルで十分なためEKF/UKFは採用しない。
- 依頼に合わせFastAPIとReact/Viteを採用。ホスティングや学校ネットワーク連携は行わない。
- 初期のローカル検証にはPython 3.12を使った。現在のサーバー用Pythonと更新方法は[サーバー設置ガイド](SERVER.md)に従う。
