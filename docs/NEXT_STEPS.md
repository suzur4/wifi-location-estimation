# 未解決課題と次の開発

## 現段階の限界

模擬データの比較と公開UJIデータの小規模建物/階分類を実行した。いずれも市川昴高校の精度・対応機器・運用可否を検証するものではない。公開UJIデータは大学のAndroid側RSSIである。教員PCへの追加ソフトなしで収集できるかは、AP管理機能などの回答が必要である。ネットワークアダプターは無効のままで、本番の認証・認可・運用は未構築である。

## 次に行う順序

1. [RESULTS.md](RESULTS.md)の誤分類と不明の内訳を調べる。単一の正解率だけで採用を決めず、要求する誤表示率と不明率を仮に定める。
2. 実行済みUJI評価（学習1,040・閾値検証390・最終テスト1,111件、[レポート](../results/uji/REPORT.md)）の失敗例を調べる。公式training内で基準地点ごとに分けて調整し、公式validation全件を最終テストにした。今後は学習上限・複数シード・欠測の距離表現を比較する。今回の最終結果を見て改良した場合、同じ公式validationの再利用を新たな独立評価とは呼ばず、追加の未使用データを確保する。元の連続性を確認できないため、時系列フィルタの優位性をこのデータの行順から主張しない。
3. 模擬環境の端末オフセット・AP欠損・日変動・未見エリアを広げる。指紋距離の欠測表現が結果へ与える影響、AP選択の安定性を検証する。スコア校正や未知検出は独立データで評価する。
4. 学校に[SCHOOL_QUESTIONS.md](SCHOOL_QUESTIONS.md)を確認する。追加ソフトなしが必須なら、管理API/RADIUS/接続AP方式から現実的な候補を絞る。
5. 許可後に小規模の静止測定PoCを実施する。教員本人の移動を記録せず、同意済みPCを既知エリアに置き、複数日・端末の学習/検証/テストを分ける。
6. 教員・生徒による表示文言と非公開操作の確認、実際のスマートフォン/ディスプレイの視認性試験を行う。障害時や端末スリープ時の不明表示も確認する。
7. 本番が必要と決まった場合に、学校の認証・役割・TLS・保持期間・バックアップ削除・監視・引き継ぎを別途設計する。開発用固定トークンを流用しない。

## 技術を追加する条件

EKF/UKF、深層学習、座標の連続推定、複数センサーは現段階で必要性を確認していない。単純手法より誤表示と不明の両面で改善する証拠、運用負担、説明可能性を示してから追加する。軌跡・速度の記録はこのプロジェクトの目的に含めない。

実際の実装・検証済み範囲と再実行方法は[README](../README.md)、[実験方法](EXPERIMENTS.md)、[実験結果](RESULTS.md)を参照する。
