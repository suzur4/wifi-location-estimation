# 未解決課題と次の開発

FSMの実装・API統合・複数シード比較は完了し、mainに統合済みである。`WIFI_FSM_ENABLED=1` で有効化できるが、既定は無効。基本の模擬/UJI実験、Ubuntu 24.04/26.04の配備試験、独立した `student-lab` 教材のWindows/Ubuntuオフライン試験も実施済みである。各結果の対象版と限界は [検証記録](VERIFICATION.md) を参照する。

次の作業は、現行版の利用者確認と実機での成立条件の確認である。模擬データの成績は学校での精度を示さず、学校ネットワークとの収集連携も未実装である。

## 優先する作業と完了条件

|順序|作業|完了を判断する証拠|
|---|---|---|
|1|FSM統合後のmainを実ブラウザで確認|候補待ち・確定・期限切れ・非公開の表示、通信停止・復帰、モバイル幅、キーボード操作の記録。jsdom試験とは区別する|
|2|Vivobookへ指定構成を配置して確認|Ubuntu 26.04 / Python 3.13.18、GitHubからの取得・更新、再起動、DB復元、スリープ設定、無線・発熱・連続稼働の実機記録。手順は [SERVER.md](SERVER.md)|
|3|学校の収集・利用条件を確定|[学校への質問](SCHOOL_QUESTIONS.md) への回答。Cisco管理方式、許可された取得経路、観測時刻と更新周期、教員PCへの追加ソフトの可否|
|4|表示の採用条件を決める|許容する誤表示率・位置不明率・確認待ち時間、非公開と障害時の動作についての合意。単一の正解率だけで採用しない|
|5|許可後に小規模の静止測定PoCを実施|同意済みPCを既知エリアへ置き、端末・日付を分けた学習/検証/テスト。教員本人の行動履歴を収集しない|
|6|実際の利用環境と教材を確認|生徒・教員による文言・視認性・非公開操作、実スマートフォン/掲示端末・読み上げ環境、学校Windowsの教材起動・印刷の記録|

実機収集では、コントローラーの古いキャッシュに新しい取得時刻を付けるだけでFSMの回数を進めないことが必要である。機器側の測定時刻・更新周期を確認し、どのイベントを新規観測として数えるかを決める。管理側から必要な情報が得られなければ、追加ソフトなしという要件を満たせるかを再検討する。

## 研究の追加評価

**FSMの確認回数と待ち時間**：既存比較では最終評価シード31〜33を分離し、各方式3,510イベント、初回正解表示、エリア変更後の遅れ、表示変動、未確定区間まで記録済みである。単純連続判定とFSMの表示結果は一致した。次は異なる観測周期・欠測の続き方・電波条件で一般化を評価する。Webの暫定3回と、模擬調整で選ばれた2回を区別し、実機条件で採用値を決める。[FSM結果](FSM_RESULTS.md)

**基本のA〜N比較**：保存済みの比較はseed42による結果であり、FSMの複数シード評価で全方式の再評価が済んだわけではない。端末オフセット、AP欠損、日変動、未見エリアを広げ、欠測の距離表現とAP選択の安定性を評価する。スコアの確率校正や未知検出率も独立データで確認する。[基本結果](RESULTS.md)

**UJIIndoorLoc**：学習1,040・閾値検証390・公式validationの最終テスト1,111件は実行済み。失敗例を調べ、学習上限・複数シード・欠測表現の比較へ進む。最終結果を見て方式を変えた場合、同じ公式validationの再利用を新しい独立評価と呼ばず、追加の未使用データを確保する。行の時間的連続性を確認できないため、並び順だけでフィルタやFSMの効果を主張しない。[UJIレポート](../results/uji/REPORT.md)

原メモとの対応は [MEMO_ALIGNMENT.md](MEMO_ALIGNMENT.md) にまとめる。ヒートマップと信頼性判定あり/なしの独立比較は追加候補である。遅延・表示変動はFSM実験で一部評価済みだが、収集から画面までの実機の遅延評価は残っている。

## 本番運用を求める場合

学校の利用者認証・役割別権限・TLS、保持期間とバックアップ削除、監視、障害対応、責任者と引き継ぎを設計し、受入れを行う。研究用トークンだけで本番認証を満たしたとは扱わない。配備・復旧スクリプトとCIはすでにあるため、学校の運用条件への適合と実機での復旧確認に進む。[情報管理](SECURITY.md)・[要件](REQUIREMENTS.md)

FSM有効時の単一ワーカー構成を超える必要が生じた場合は、複数プロセス間での確認証拠の管理を別途設計する。現行の外部DB更新検知は証拠を破棄するための処理であり、回数の共有ではない。

## 技術を追加する条件

EKF/UKF、深層学習、座標の連続推定、複数センサーは、単純手法より誤表示・不明・待ち時間を改善する証拠、運用負担、説明可能性を示してから追加する。カルマン＋FSMにもエリア変更時の遅れがあり、組み合わせるだけで安全になるとは判断しない。軌跡・速度の記録は目的に含めない。
