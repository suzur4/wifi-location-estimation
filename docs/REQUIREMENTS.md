# 要件と制約

本書は2026-11-04時点の研究用プロトタイプの要件である。作業開始時に既存コードと指定の研究メモはなかった。ユーザーの依頼文を原本として設計した。

## 目的

既存Wi-Fi設備から得られる情報で、教員が使うWindows PCの大まかなエリアを推定する。PCを置いて移動した教員の所在は分からない。生徒は通常のブラウザで名前・教科を検索する。生徒の端末へのアプリ導入は不要とする。

## 確定した開発範囲

- 固定シードの模擬観測、CSV、UJIIndoorLocの入力。実測と模擬を出所で区別する。
- 接続AP、最強RSSI、1-NN、k-NN、距離重み付きk-NN、順位、ガウス型のエリア分類。
- なし・平均・中央値・外れ値に頑健な平均・EMA・一次元カルマンの因果的前処理。
- 学習・検証・テストの分離、A〜H比較、閾値・AP数・端末・日時などの補助評価、再実行可能なCSV/JSON/図/レポート。
- FastAPI、SQLite、React/TypeScript/Viteによるローカル画面。架空教員、検索、ディスプレイ、開発管理、研究可視化。
- 少ない観測、古い観測、未知AP、未知パターン、競合候補を`unknown`として扱う。
- 非公開なら位置・時刻などの公開情報を抑える。生徒APIに端末ID・MAC・RSSIを含めない。

## 未確定の仮定

APの申告型番はCisco AIR-AP1832I-Q-K9C。現在の管理方式、管理API、RADIUS、SNMP、認証方式、VLAN、APの設置位置は管理者への確認事項。[機種と取得方式](NETWORK.md)。4AP・6エリア、3種類の端末オフセット、静止測定セッションは実験上の仮定であり学校の実配置ではない。初期の鮮度180秒・距離24dB相当・候補差0.05などは実装開始用の値であり、学校で承認された仕様ではない。公開データのAndroid側RSSIとAP側RSSIは同じ観測量とは扱わない。

教員PCへの追加ソフト不要を優先するが、管理側から十分な情報が取れなければ達成できない。ブラウザだけでPC周囲のBSSID/RSSIを収集できる構成は採用しない。API権限・機器対応が判明するまでは学校ネットワーク連携を無効にする。

## 行わないこと

学校ネットワークのスキャン・監視、AP/スイッチへの接続、無断のPC情報収集、実在教員の登録、軌跡・速度推定、外部公開、本番導入。管理用トークンはローカル架空データの開発専用であり、実運用の認証仕様を満たさない。

## 受入れと評価

READMEの手順でデータ生成、比較実験、テスト、Web起動を再現できること。各結果にソース・条件・実験IDを付ける。正解率だけでなく、誤表示率・不明率・表示した結果に限った正解割合を並べる。実行記録は[RESULTS.md](RESULTS.md)に保存する。学校での精度と利用可否は実機PoCの後に判断する。
