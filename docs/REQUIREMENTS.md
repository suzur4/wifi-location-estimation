# 要件と受入れ条件

本書は、FSMを統合したmainの研究用プロトタイプが扱う範囲と、実校内で使う前に確定すべき条件を示す。実装・検証済みの内容と、学校向けの目標を区別する。確認済みの版・環境は [検証記録](VERIFICATION.md) を参照する。

## 利用目的

既存Wi-Fi設備から得られる情報を利用し、教員が使うWindows PCの大まかなエリアを推定する研究である。PCを置いて移動した教員本人の所在は分からない。生徒は通常のブラウザで名前・よみがな・教科を検索し、エリア、位置不明、非公開を区別できるものとする。生徒端末への専用アプリ導入は不要とする。

現行Webは架空教員と模擬観測で動く。教員PCへ追加ソフトを入れずに測定を取得できるかは未確定で、学校のAP管理機能と許可条件に依存する。ブラウザだけで周囲のBSSID/RSSIを収集する方式は採用しない。

## 満たすべき表示・保存条件

- 古い観測、観測不足、未登録AP、未知パターン、競合候補は、推定方式の判定条件に応じて位置不明にする。確信のある現在地として補完しない。
- Webの鮮度期限は測定から180秒。180秒以上でエリアを隠し、5秒を超える未来時刻も表示しない。通信が止まっても画面側で再判定する。
- 生徒APIに端末ID・MAC・AP識別子・RSSI・管理トークンを含めない。非公開では場所と測定時刻を隠し、保存済みの最新観測を削除して新しい観測も受け付けない。
- SQLiteの観測は対象ごとの最新1件だけとする。既定の保持期間は1時間。表示期限とは別に削除を行い、行動履歴を蓄積しない。
- FSM有効時は候補段階を位置不明にし、GETや同じ測定の再送で確認回数を増やさない。再起動や推定設定の変更後は新しい証拠を集め直す。APIは単一ワーカーで動かす。
- 管理操作にはトークンを要求する。これは研究用のアクセス制御であり、学校向けの利用者認証・役割別権限を実装したことにはならない。

## 想定機器と未確定事項

サーバーの対象はASUS Vivobook 16 V3607VU_V3607VU（Intel Core 7 240H、16GB、RTX 4050 6GB、Realtek 8852BE）、指定OSはUbuntu 26.04、アプリ用Pythonは3.13.18である。同じOS/Pythonの自動試験とsystemd配備はCIで確認済みだが、このVivobook実機のドライバー・無線・スリープ・連続稼働は未検証である。

APの申告型番はCisco AIR-AP1832I-Q-K9C。管理方式、ファームウェア、管理API、RADIUS/SNMP、認証方式、VLAN、設置位置、観測時刻・更新周期は学校管理者への確認事項である。機種名だけから取得できるRSSIの種類や必要権限を確定しない。[機器と収集方式](NETWORK.md)・[学校への質問](SCHOOL_QUESTIONS.md)

4AP・6エリア、端末オフセット、静止セッションは模擬実験の仮定であり、学校の実配置ではない。Webの推定閾値とFSMの既定3回は暫定値で、学校の精度・応答時間要件を満たす最適値ではない。公開データのAndroid側RSSIとAP側RSSIも同じ観測量として扱わない。

## 受入れの基準

研究用プロトタイプでは、READMEの手順で環境構築・テスト・Web起動・比較実験を再現できることを基準にする。結果にはデータの出所、条件、実験ID、分割、指標の分母を付ける。正解表示率・誤表示率・位置不明率・表示時の正答率を併記し、FSM比較では待ち時間と最後まで確定しなかった区間も示す。

学校での利用可否は、許可された別端末・別日の測定を使うPoCで判断する。採用基準となる誤表示率・不明率・更新周期、非公開操作、障害時表示、認証・権限・TLS・データ保持・引き継ぎは学校側と合意する必要がある。現在の模擬結果やCI成功だけではこの受入れを満たさない。

## 対象外

無断の学校ネットワークのスキャン・監視、AP/スイッチへの接続、PC情報収集、実在教員の登録、外部公開、本番導入は行わない。許可済みの小規模PoCは [未解決課題と進め方](NEXT_STEPS.md) に従って別途計画する。軌跡・速度推定や行動履歴の蓄積は本プロジェクトの目的に含めない。
