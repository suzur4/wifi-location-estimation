# 情報管理とプライバシー

このプロトタイプはローカルの架空データ用である。学校・教員の許可はまだない。学校ネットワークの探索・接続、実在教員やPCの収集、外部公開は行わない。

## 研究用と公開用の境界

- 研究データは`source`と実験IDで模擬・公開・将来実測を区別する。公開データの個人識別フィールドを学校の人物へ対応付けない。
- 教員表示情報と端末対応は別の責務とし、生徒APIは明示的な表示項目だけを返す。端末ID、MAC、AP、RSSI、セッションIDは含めない。
- 生徒画面はPCの推定エリアであると表示する。教員本人の現在地や在校を保証しない。
- 非公開の場合、エリアに加えて更新日時・診断理由も公開しない。非公開の切り替えは管理APIに限定する。
- Web DBは最新状態のみを扱い、移動経路・速度・履歴の蓄積を行わない。匿名の静止測定用ファイルは実験目的で別管理する。
- 一定時間を超えた観測は再表示時にも`unknown`にする。古い情報の削除と、古い情報を表示しない処理は別であり、保持期間の合意が必要。

## 開発時の制御

管理APIはBearerトークンで保護する。以前は誰でも知っている固定値`dev-demo-token`が既定で、画面のソースにも埋め込まれていた。2026-11-04に、`WIFI_ADMIN_TOKEN`が未設定なら起動ごとにランダムなトークン（`secrets.token_urlsafe`）を作り、ターミナルにだけ表示する方式へ変えた。16文字未満の値を設定した場合は起動時に警告する。画面はトークンを自動入力・自動送信せず、利用者が入力した値をReactのメモリ内だけで保持する（`localStorage`・`sessionStorage`に保存しない）。「接続を解除」の後に遅れて返った応答は、画面に反映しない。比較は`hmac.compare_digest`で行う。PCの共有利用・ブラウザ拡張などからの秘匿を保証するものではない。管理者向け画面・研究用診断を校内の生徒向け公開URLへそのまま出さない。

開発サーバーは`127.0.0.1`にbindする。ただし127.0.0.1に限定しても、悪意のあるWebページが自分のドメインの名前解決を127.0.0.1へ差し替える「DNSリバインディング」で、ブラウザ経由でAPIを呼べてしまう。固定トークンと組み合わさると管理APIまで操作できたため（確認時、`Host: attacker.example`で管理一覧が200で返った）、次の対策を入れた。

|対策|内容|
|---|---|
|Hostヘッダーの検査|`127.0.0.1`・`localhost`・`[::1]`以外は400。変更は`WIFI_ALLOWED_HOSTS`（カンマ区切り。ポート番号は除き、IPv6は角かっこ付きに直して比較）|
|トークンの文字|半角の英数字と記号のみ。全角文字や空白を含む`WIFI_ADMIN_TOKEN`はHTTPヘッダーで送れず一致しないため、起動時にエラーにする。画面でも送信前に確認する|
|セキュリティヘッダー|`Content-Security-Policy`（自サイトのスクリプト・スタイルのみ、`frame-ancestors 'none'`）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`など。`/docs`のSwagger UIはCSPの対象外|
|キャッシュ|`/api/`は`no-store`（非公開化後の古い所在がキャッシュに残らない）、画面の`index.html`は`no-cache`、ハッシュ付きの`/assets/`は長期キャッシュ|
|送信サイズ|リクエスト本文は32KiBまで（`Content-Length`がない分割送信も数えて413）。静的ファイルの送信が始まった後に届いた本文は、例外にせず読み取りをやめる|
|入力の検査|名前・教科・端末ID・AP識別子の改行・制御文字・文字の向きを変える書式文字（例：U+202E）・ゼロ幅文字・私用領域の文字を拒否（Unicodeの新しい漢字に備え、未割り当ての文字は拒否しない）。未定義の項目は422。よみがなはひらがな・カタカナのみで、互換文字を展開した後も60文字まで。検索語は100文字まで。検証エラーは「名前は60文字以内で入力してください」のような日本語で返す|
|保持期間|最新測定は`WIFI_RETENTION_SECONDS`（既定3600秒、1秒〜10年）を過ぎると、起動時・一覧の取得時・1分ごとにDBから削除する。保持期間より古い日時の測定は保存しない。3分の表示期限とは別。値は仮置きで、学校との合意が必要|
|削除|管理画面から架空の先生を削除すると、その先生の最新測定も同じトランザクションで消す|

管理用値を公開リポジトリに書かず、実機連携を既定で無効にする。受信する日時、RSSI、名前・ID等を検証する。検証エラーは入力値をそのまま返さず日本語の短い説明にする。実行ログにMACや資格情報を書かない（起動時のトークン表示は、起動した本人のターミナルに対するもの）。推定不能なデータを補って架空の実測にしない。

## 実運用前に決定が必要な事項

学校の承認と教員本人の同意、任意参加/取り消し、公開先（生徒・校内端末・職員室前）、アクセス制御、TLS、本人認証、管理者の役割、秘密の保管・ローテーション、脆弱性対応窓口を決める。職員室前ディスプレイでも来訪者から見える可能性を考える。

RSSI観測、最新エリア、AP台帳、端末との対応、学習用指紋、アクセスログそれぞれの保持期間と削除責任者を決める。「最新のみ」はバックアップやログに残らない保証ではない。バックアップの削除と情報公開停止を含めた手順を検証する。利用者が誤表示を報告・訂正できる運用も必要である。

SNMP・RADIUS・AP API等は読み取り専用かつ対象を限定した権限を使う。ネットワーク管理者の承認を得てから実装し、校内の資格情報をチャットで要求・推測しない。WindowsのWi-Fi情報取得には位置情報への同意が関係する。[Microsoft公式説明](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes)。

本書は学校の運用規程や法的判断を確定するものではない。個人情報を使う段階の審査・合意はプロトタイプ完成とは別に実施する。
