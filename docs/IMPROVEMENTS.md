# 品質改善の記録（2026-11-05）

この文書は2026-11-05に修正した不具合と、その時点の回帰確認の記録である。その後のサーバー対応・FSM統合を含む現在の仕様は[アーキテクチャ](ARCHITECTURE.md)、最新の確認範囲は[検証記録](VERIFICATION.md)を参照する。学校ネットワークや実在教員のデータは使用していない。

## 保存・更新の整合性

- **全件削除後の復活を防止。** 全6名を削除して同じDBで再起動すると、6名が復活していた。新規DBの初回だけ自動登録し、初期化済みの状態を記録する。既存DBは空でも再登録しない。再起動・旧スキーマ移行のテストで確認した。
- **模擬更新を一括保存。** 許容範囲の現在時刻＋3秒の測定があると、模擬更新が途中まで保存されて409になっていた。新しい測定は保持し、残りを1トランザクションで更新する。応答の`updated_count`と`skipped_newer_count`で件数を返す。途中の書き込み失敗は全体を取り消す。非公開化・削除も同じロックとトランザクションで処理する。
- **研究結果の破損を明示。** 書き込み途中のJSON、必須指標の欠落、非数値・不正な範囲を503の日本語エラーにする。結果ファイルが未作成の場合は従来どおり未実行として扱う。研究画面に再試行を追加した。正常な結果へ置き換えた後の復旧も検証した。

## 通信と入力

- **以前の管理接続の応答を無効化。** 接続・再取得・変更後の処理を接続世代で管理し、切断や画面離脱の後に届く応答が管理データや設定を戻さないようにした。
- **設定情報を独立して復旧。** エリア名・推定方式を教員一覧と別々に受け取り、一方の失敗で他方を破棄しない。通常更新・通信復旧・「設定を再読み込み」で再試行する。教員一覧が成功しても設定のエラーを消さず、保存前に始まった古いGETで保存後の設定を戻さない。
- **入力を保持。** 登録の保存中は入力を読み取り専用にし、次の入力が保存完了時に消えることを防いだ。未保存のAP対応表は、別の操作に伴う再取得で上書きしない。保存完了後に一覧の取得だけが失敗した場合は、保存自体の失敗と区別して知らせる。

## 推定・評価

- **Gaussian分類の候補を制限。** 共通APが足りない学習行を距離計算から除外しても、そのエリアがGaussianの候補に戻っていた。共通AP条件を満たす学習行があるエリアだけを候補にする。欠損値の代入だけで、照合できるAPがないエリアを選ばない。
- **正解ラベルのない評価を拒否。** `evaluate`に正解`unknown`を渡すと、棄却を正解にも数えて誤表示率が負になっていた。既知エリア評価では欠落・空白・`unknown`の正解ラベルを予測前に拒否する。未知エリア検出の評価は別途設計が必要。
- **最強AP方式を学習データから独立。** AP対応表と現在の観測から判定する。最小AP数、選択したAP、未登録の最強AP、測定の鮮度の条件は維持する。

## 実験の再確認

修正後の模擬seed42実験とUJI実験を、既存成果物とは別の一時ディレクトリで再実行した。

- 模擬の観測CSVと予測4,032行は、既存成果物とバイト単位で一致。
- 模擬A〜N、端末・日付別、AP選択、閾値、欠損、フィルタ変動の指標は、実行時間を除き一致。
- UJIの4方式は、実行時間を除く指標・閾値・判定理由が一致。

入力と修正後コードのSHA-256を含む[比較記録](verification/improvement-regression.json)を保存した。`results/latest`と`results/uji`は元の実行記録として保持した。同じデータを使った回帰確認であり、新しい独立した精度評価や学校での性能向上を示すものではない。
