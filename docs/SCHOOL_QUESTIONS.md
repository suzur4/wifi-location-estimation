# 学校側に確認する事項

利用予定のAPとしてCisco `AIR-AP1832I-Q-K9C` の申告を受けている。学校には以下の仕様・許可範囲・担当窓口を確認する。

## 目的と同意

- 教員PCの推定エリア表示という目的に学校の承認が得られるか。教員本人への説明と任意参加・非公開・取り消しの方法は何か。
- 生徒、校内ネットワーク、職員室前ディスプレイなど、誰に何を表示するか。校外・来訪者からの閲覧を許すか。
- PCを教室に置いて本人が移動する場合など、誤解を防ぐ文言・運用を誰が決めるか。
- 許容する誤表示率、不明率、更新間隔、情報の有効期限、表示するエリアの粗さは何か。

## ネットワーク仕様

- 申告機種はどのエリアに何台あり、ほかの機種と混在するか。管理はMobility Expressのコントローラー役APか、外部WLCか。運用中のソフトウェア版と機器更新予定は何か。[型番・サポート期間と確認手順](NETWORK.md)
- 同一SSID・複数帯域・仮想BSSID、VLAN、トンネル終端、ローミングをどう構成しているか。
- 読み取り専用の管理API、クライアント接続AP、RSSI、取得時刻を出せるか。RSSIはAP側かPC側か。単位・更新周期・期限・料金は何か。
- SNMPv3のBRIDGE-MIB/FDBとポート/AP台帳を参照できるか。クライアントMACがどの装置・ポートへ学習されるか。
- 802.1X/RADIUS Accountingはあるか。Called-Station-Id・NAS ID・Interim Update・ローミング時の属性を許可された匿名出力で確認できるか。
- 管理者の担当、実験用ネットワーク、対象ホストと時間帯、問い合わせ・停止手順は何か。

## Windows端末

- OS版、Wi-Fiアダプター、ドライバ、スリープ・切断、持ち歩き、MACランダム化などの条件は何か。
- 管理側の情報だけで足りない場合、学校管理下の収集スクリプトやエージェントは許可されるか。追加ソフト禁止を必須条件とするか。
- 位置情報同意・グループポリシー・端末IDと教員の対応を誰が管理するか。個人利用端末は対象外にできるか。

## データと運用

- 実測の場所・期間・担当者・参加端末・正解ラベル記録をどう決めるか。複数日・複数端末の独立評価が可能か。
- RSSI、端末対応、最新結果、学習指紋、アクセスログ、バックアップの保存場所・保持期間・削除責任者は誰か。
- 校内認証、役割、通信暗号化、障害・誤表示・同意撤回・AP交換時の対応をどうするか。
- コンピューター部と大学生のアクセス権、卒業・担当交代時の引き継ぎ、保守予算・責任者は誰か。

回答後、まず許可された1AP/少数の架空または同意済み端末による閉じたPoCを設計する。[NETWORK.md](NETWORK.md)の手順と[SECURITY.md](SECURITY.md)の境界を更新する。本番導入や全校の収集はこの質問票の提出だけで承認されたとは扱わない。
